Status: OPEN, blocking, no dismissal requested through a mutating API. Evidence inspected on b575187d3f3d46b8f0abfaea4687f1544222f0b1, SARIF analysis 1888906934.

## Actual data path

The insufficient-password-hash finding follows requestPasswordResetByAuthority (lib/auth/password-reset-authority.ts:40) into deliverCoreV2PasswordReset, then enqueueEmailIntent and idempotencyKey (lib/email/outbox.ts:123). This sink creates a message deduplication identifier, not a password verifier. The reset proof is an opaque CSPRNG 32-byte token generated by createAccountToken; the account service persists its dedicated versioned HMAC digest. The raw proof is needed only inside the encrypted mail intent to deliver the activation/reset link. User-chosen passwords are handled by the existing password KDF, not by this outbox HMAC.

The outbox derives a key from EMAIL_OUTBOX_ENCRYPTION_KEY and uses AES-256-GCM with a fresh IV and authenticated metadata for the payload. Dedupe input consists of message type, aggregate identity and a transition key (the reset token digest for this emitter). The resulting HMAC prevents exposing that input as the outbox key. Replacing this primitive with a password KDF would conflate deduplication with authentication. Changing encryption key derivation without a versioned compatibility plan would make queued payloads unreadable.

## Limits and required authority

Key configuration checks only a minimum character count: actual production entropy, secure custody and rotation are not proved here. The v1 payload key version has no demonstrated dual-key rotation procedure. These operational gaps remain open. This document is a narrow false-positive assessment proposal, not authorization to dismiss the alert and not proof of all email security. An authorized security reviewer must inspect the final SHA, confirm the dedicated random key and scope, and decide disposition through repository governance. Any future change to the source/sink invalidates this proposal; any temporary decision needs a named owner and explicit expiry. No whole-rule exclusion, renamed credential or blanket suppression is proposed.

Three existing outbox/worker/maintenance suites pass locally (11 tests, 0.768 s), including encrypted content, authentication-tag tampering, stable message identities, retries and maintenance. They do not qualify real delivery, production key rotation or retention.
